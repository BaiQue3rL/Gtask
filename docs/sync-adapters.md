# 同步适配器边界

## 公共基准维护

本节描述的是 Agent 的基准维护模式。用户明确要求软件维护时，Codex 可按软件维护授权使用更宽的本机 MCP 和工程工具，但这不改变下面的个人同步职责，也不能在基准任务中隐式切换模式。

后台维护任务通过本地 stdio MCP 领取 `public_catalog`，联网核验活动、周期、地图或版本窗口，并提交结构化结果。应用只校验类型、稳定身份、两级地图、时间窗、来源证据和事务边界。该流程不在普通用户界面出现，不读取凭据或个人数据，也不提交完成状态和探索度。

## 个人进度

原神、崩坏：星穹铁道和绝区零使用米游社；鸣潮使用库街区。凭据由主进程通过 Windows DPAPI 加密保存，不进入渲染进程、维护任务或日志。

适配器只访问对应官方接口，输出：

- 稳定官方身份；
- 可验证的活动匹配信息；
- 本期手动挑战记录；
- 地图探索百分比；
- 完整性、适配器版本和脱敏账号作用域。

协调器按目标版块过滤和规范化数据。数据库仅把进度写到唯一匹配的公共基准行；个人输出不能新增、改名、归类、重设时间、增加标签或改变地图父级。无法匹配的记录计为保护项并忽略。

个人同步不调用公共周期目录补全、档期预测、到期删除或时间校准。接口携带的档期字段只能辅助唯一匹配，或脱敏后另存为 Agent 的维护观察，不能反向维护基准。地图个人快照若提供一级地区探索度，一级值优先并跨重启保留；只有未提供一级值而提供了二级值时，应用才按完整公共二级目录计算平均值。限时活动到期删除、周期/版本到期滚动是独立于个人同步的运行时生命周期，并且只能执行基准中已经发布的时间和规则。

只有目标接口完整成功才提交事务。部分响应、限流、人工验证、凭据失效、取消和解析失败都保留上次数据。相同平台请求保持串行，避免瞬时并发触发风控。

## 活动完成证据

每个接口有自己的完成语义，不能由一个通用函数猜测所有名为状态或进度的字段。`event-completion-evidence.ts` 集中登记已验证规则，活动候选强制携带 `completionEvidence`（已完成、未完成或未知，以及规则和字段），共同规范化与写入链路保留并校验证据。新增接口必须实现此契约，不再允许只有含糊状态载荷而被静默忽略。

2026-10-13 对国服官方日历的现场核验，保留无账号标识的最小形状于 `tests/fixtures/personal-event-calendars.json`：

| 接口 | 已核验的完成字段 | 边界 |
| --- | --- | --- |
| 原神 `act_calendar` | `is_finished` 严格布尔值 | 生命周期 `status`、子玩法探索度不替代整个活动完成 |
| 星铁 `get_act_calender` | `all_finished` 严格布尔值 | 双倍奖励存在 `current_progress=0,total_progress=12,all_finished=true`，也存在 `84/84,all_finished=false`；数字不能统一解释为已完成数 |
| 绝区零 `activity_calendar` | `STATE_COMPLETED` 为完成、`STATE_IN_PROGRESS` 为未完成 | 同一正在开放的时间窗内，弹球活动返回前者，未完成活动返回后者；此 `state` 是玩家状态。奖励数量不作判据，其他枚举保留未知 |

官方入口：[米游社绝区零战绩](https://act.mihoyo.com/app/mihoyo-zzz-game-record/m.html)。实际数据分别来自代码中的国服官方战绩 API；核验脚本只在本机内部复用加密凭据，不输出或存储 Cookie、UID、角色或设备标识。此处核验的是这些字段的契约，不意味着官方接口覆盖所有活动、所有关卡或全部非菲林目标。

官方前端当前首页代码 [`m_25028b9f.js`](https://act.mihoyo.com/app/mihoyo-zzz-game-record/m_25028b9f.js) 同样以 `isCompleted: state === STATE_COMPLETED` 生成活动卡片，并另外定义 `STATE_NOT_START`、`STATE_END` 生命周期状态。因而只把经核验的前两个枚举投影为个人完成证据，生命周期状态不推断玩家是否做完。

缺失或非法完成字段、新枚举返回未知并保留已存进度；列表缺失、列表夹杂非法条目或重复官方标识应拒绝本次目标同步。明确空列表与漏项报告为“接口未返回”，不当作明确未完成。写入回执分别统计已确认完成、未完成、无法判断、未返回、未匹配、手动保护；未知结果和手动保护不能取代旧的可靠证据快照。完成证据与奖励数量不进入公共档期观察，也不改变公共清单。

版块同步状态只表达本次请求与写入是否成功；成功显示“已同步”和同步时间，失败或验证异常按实际请求结果显示。接口没有返回某项个人记录可能只是该活动尚未进行，不能据此将成功同步显示成“部分进度待确认”。完成判定的准确性与同步成功是两层职责，证据和覆盖统计保留在内部同步回执，不参与界面的成功状态或悬停说明，也不额外缓存展示摘要。

## 周期完成证据

周期模式只有在官方响应中存在本期必须手动完成目标的可靠记录时才算完成；玩家不需要满星、满分、最高层或清空全部奖励。完成证据必须来自适配器已验证的手动记录布尔标记、正数手动战绩或战斗明细。自动继承、减负结算、扫荡、快速通过/快速解锁、汇总星数、预生成关卡/阵容结构都不是证据；鸣潮终焉矩阵的 `passBoss` 只表示快速通过结果，不能单独算完成。

鸣潮战绩响应中的 `seasonEndTime` / `endTime` 数值不具备可验证的 Unix 档期语义，不能用于判断当前期、过期或维护公共时间。鸣潮个人适配器只提交手动挑战完成证据；周期起止时间和当期身份始终由公共基准负责。
