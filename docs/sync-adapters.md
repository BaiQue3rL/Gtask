# 同步适配器设计

## 点击刷新后发生什么

界面不会等待 AI 对话来“看见”按钮。流程是确定性的：

1. 渲染进程把当前游戏、版块和动作通过安全 IPC 发送给主进程。
2. “同步清单”只创建公开资料任务；“同步进度”只运行米游社或库街区个人数据适配器。
3. 软件不做启动自动同步；所有同步都由用户手动发起。
4. 全局刷新只提供“同步清单”；“同步进度”只存在于具备个人接口能力的版块。离线时由用户手动新增或编辑事项。
5. 每个来源先做运行时校验；含义明确的数据进入安全合并，含义不明确的数据必须停在待核验状态，不能靠字段名或数值猜测。
6. 主进程返回新增、更新、受保护数量和来源级状态，界面重新读取清单及同步时间。

同一游戏的相同并发刷新会复用正在运行的任务；不同范围会排队，避免同时写入和重复请求。

## 公开资料来源

优先级为：

1. 官方公告、官方活动页或可验证的官方结构化数据。
2. 有稳定维护记录的社区排期数据，作为补充来源。
3. 官方或社区资料图片只能作为 Codex 联网核验时的辅助证据；应用不做本地 OCR。离线时不自动识别，用户可直接手动填写。

每份公开资料文档必须保存 `sourceUrl` 和 `fetchedAt`。用户在事项编辑器中可以查看来源链接。公开资料只能写限时活动、周期挑战和已开放地图区域，不能声明个人完成状态或个人探索进度；公开地图首次写入固定为 0%。

文档格式：

```json
{
  "schemaVersion": 1,
  "gameId": "genshin",
  "sourceUrl": "https://example.com/official-schedule",
  "fetchedAt": "2026-07-20T01:00:00.000Z",
  "items": [
    {
      "remoteKey": "event:stable-official-id",
      "category": "limited_event",
      "title": "活动名称",
      "startsAt": "2026-07-20T02:00:00.000Z",
      "endsAt": "2026-08-01T02:00:00.000Z"
    }
  ]
}
```

## 个人数据来源

- 原神、星铁、绝区零：应用内独立米游社登录。
- 鸣潮：设置页导入库街区 App Token 与对应 DID，读取官方角色列表并选择角色；只有官方 BAT 刷新校验成功才通过 DPAPI 保存。
- 不读取或自动提取 Chrome Cookie。
- 凭据经 Electron `safeStorage` 加密，Windows 下由 DPAPI 保护；磁盘只保存加密字节。
- 未登录、凭据无法解密、登录过期或触发 Geetest 时返回 `verification_required`，不删除上次成功数据。

个人数据只采用官方语义已经验证的完成状态、战绩和探索百分比。字段名、枚举值或数值含义未被官方文档或真实样本证明时，不得据此生成完成状态。公开资料已经存在时，优先按官方 ID 合并，活动可按中文名称与重叠时间窗口兜底，地图可按中文区域名兜底；个人数据只补可信的个人字段，不覆盖公开中文名称和时间。地图解析必须保留官方父子区域关系；父项为 0 而子项有进度时不得用简单平均数伪造探索度，只有全部直接子项均为 100% 时才可确定性地将父项判为 100%。

界面按最终产品能力声明个人同步入口：原神开放活动、周期和地图；星铁开放活动和周期；绝区零开放活动和周期；鸣潮开放周期和地图。开发阶段不会因为授权链路暂未验收而反复隐藏最终需要的入口。三款米游社游戏的活动原始状态全部只进入 Codex 语义核验队列，本地不再按状态枚举、标题关键词或无时区文本直接判分类、时间与完成。同版块包含多个接口时顺序请求，部分接口失败仍保留已成功结果，只有全部失败才判定本次版块同步失败。

## Codex 语义核验架构

公开资料同步已经采用 Codex 先检索、核对中文名称和分类，再通过 MCP 提交结构化结果的流程。个人数据适配器后续也遵循同一原则，但必须先在本机提取和脱敏：

1. 本地连接器负责登录、请求和提取原始字段，不把 Cookie、UID 等凭据交给 Codex。
2. 只有结果可证明唯一的机械规则才允许本地直接处理，例如 Unix 时间戳转绝对时刻、数值范围校验、稳定官方 ID 精确匹配和 `1 + 1 = 2`。
3. 新活动名、新挑战名、未知枚举、自然语言日期、来源时区、跨服时间、分类和完成语义都必须交给 Codex；软件不得依靠关键词、字段名或历史猜测。
4. Codex 不可用或置信度不足时，软件只生成“待 AI 核验”候选，不直接写完成状态、分类或推测时间；离线用户可选择手动填写。
5. Codex 结合接口上下文和中文官方资料，返回类别、规范中文名、完整时间窗口、置信度和逐项证据。
6. SQLite 写入层拥有最终否决权：禁止跨版块、禁止未来活动完成、禁止公开资料声明个人完成、禁止非地图百分比、禁止无明确 UTC 偏移的活动时间。

Codex 负责理解语义，软件负责凭据隔离、硬规则校验和事务落库。即使 AI 不可用，手动清单和已有可信数据仍完整可用。

## 已实现的游戏解析

原神已接入个人活动完成/活动探索、区域探索、深境螺旋、幻想真境剧诗和幽境危战；原神区域探索同时解析 `parent_id` 和 `area_exploration_list`，避免把父级容器的零值当作真实探索度或漏掉嵌套区域。星铁接入混沌回忆、虚构叙事、末日幻影和异相仲裁。三种常规星铁模式以到达本期最后关作为完成条件；异相仲裁要求首领与全部小头目记录均完成。星铁活动日历中的 `all_finished`、`OtherActStatusFinish` 和当前/总数值不再由本地程序解释：只提取官方活动 ID、中文标题、确定性时间戳和原始状态值，剔除 UID、Cookie、Token 等信息后进入 Codex 队列。Codex 低于 0.9 置信度或无直接证据时必须拒绝，不修改清单。米游社目前没有为星铁、绝区零提供与原神同口径的区域探索百分比，因此这两款游戏由公开资料建立区域目录，不伪造个人百分比。

绝区零已根据脱敏实测响应实现：

- 式舆防卫战：稳定模式标识、`schedule_id` 周期、起止时间、第五防线完成状态和分数进度。
- 危局强袭战：稳定模式标识、周期 ID、起止时间、逐挑战满星完成判断和星数进度。
- 活动日历：官方活动 ID、起止时间、完成状态以及菲林领取进度。

所有游戏共用以下落库保护：未开始的限时活动不能被远端标记完成；只有地图探索保存百分比；应用启动会清理历史自动误判，但保留用户手动完成锁。AI 写入限时活动时必须同时提供带 `Z` 或明确 UTC 偏移的开始和结束时间。

米游社二维码登录、角色发现、DS 签名和上述绝区零接口已经接入正式桌面链路。二维码确认后，Cookie 仅以 DPAPI 加密文件落盘；点击“同步进度”只运行个人适配器，不会排队公开资料任务。版块独立刷新从请求层只调用对应接口，旧公开任务排队不会阻断个人请求。遇到 Geetest 时打开受限人工验证窗口，验证成功后只携带本次票据重试一次；用户取消不会删除最后一次成功数据。原神和星铁会按账号生成稳定设备 ID，向官方接口注册对应指纹，并在战绩请求中成对发送设备 ID/指纹，避免用一个设备注册指纹却只提交另一半身份；绝区零部分接口对设备头更敏感，因此继续使用已经实测通过的无设备头请求组合。

库街区短信 + Geetest V4 在 Electron 窗口中加载不稳定；库街区官网 Web 登录虽然能完成，但官网回传的 Web 访问令牌会被个人战绩角色接口判定为“登录已过期”。两条未证明可用的登录链路及其界面、IPC、临时会话均已移除。当前采用成熟社区工具也使用的 App Token + DID 直接导入方式：应用只访问库街区官方角色与战绩接口，不共享机器人凭据池。鸣潮个人客户端已接入 `exploreIndex`、`towerDataDetail`、`slashDetail`、`newTowerDetail` 与 BAT 刷新，仍需真实账号完成端到端验收。

真实原神探索验收已复现“人工验证完成后仍返回验证要求”。这不是解析或数据库写入失败，而是请求在拿到探索响应前再次被米游社风控拒绝。若设备身份复用后仍不稳定，合规兜底为应用内隔离的米游社官方战绩页会话：用户在官方页面自行登录和完成验证，应用只读取该会话中用户已授权的战绩响应；不读取 Chrome Cookie、不自动破解验证码，也不把临时 Python 探测依赖纳入正式架构。

## 网络与代理

公开资料 HTTP loader 已作为适配器依赖实现，并统一强制：

- HTTPS 和精确域名白名单。
- 最多 3 次手动跳转，并对每一跳重新校验协议和域名。
- 默认 12 秒超时和 1 MiB 响应上限。
- 无 `Content-Length` 时仍流式执行 1 MiB 上限。
- JSON 内容类型、UTF-8 解码、JSON 解析和 24 小时文档时效校验。
- 每份文档最多 500 条事项；超过上限整批拒绝，不进入数据库事务。

代理配置仍放在传输层，不进入清单合并逻辑；这样直连与代理返回的数据会经过完全相同的文档校验和事务保护。首个真实来源接入前还需要确定代理实现与来源白名单。

桌面端已提供 `createElectronNetFetcher` 传输适配器和 `createElectronPublicScheduleAdapter` 装配工厂。真实来源接入时由主进程在 `app.whenReady()` 之后注入 Electron `net.fetch`，再提供游戏 URL 与精确域名白名单；请求会使用 Chromium 网络栈并跟随 Windows 系统代理，同时强制绕过应用自定义协议处理器。测试和 CLI 仍可注入普通 `fetch`，不会让代理策略渗入解析与合并层。
