- 内置版本、活动、周期、地图目录由公共持久基准表所有。
- 米游社/库街区完整个人 snapshot 只更新完成状态、探索度和官方来源绑定，不拥有标题、时间、标签或地图层级。
- 不得重新引入公共数据与个人数据的自动融合、个人语义复核或个人元数据补标链路。
- 自定义版块保持用户 CRUD；内置卡片不提供新增、编辑和删除。
- 地图严格只有 `region` 与 `subregion` 两级，不得增加第三层或“独立地图”节点。
- 已发布的地图 `remoteKey` 必须稳定。改名应保留旧机器身份，不能按新标题重新生成键。

## 强制数据规则

### 版本

- 四款游戏都必须有当前正式版本的 `startsAt` 与 `endsAt`。
- 优先使用官方明确的下一次维护时刻；尚未公布时才允许有依据的暂定值。
- 不得用卡池、单个活动或奖励领取期限冒充版本结束时间。

### 活动

- 每条活动必须有准确 `startsAt`、`endsAt` 和来源。
- 每条活动必须有 1–5 个有效稳定标签 ID；不得留空、猜测或用“活动”等泛化标签凑数。
- 一个官方活动容器只建一条记录；内部阶段、商店、关卡、奖励档位和卡池不单独建项。
- 修改内置活动后必须通过活动时间、标签质量和稳定身份测试。

### 周期挑战

- 每个内置周期模式必须始终得到当前期明确起止时间，不能再生成无时间占位卡。
- `modeKey` 和 `remoteKey` 表示稳定模式；`periodKey` 表示当期实例。
- 换期前保存上一期历史并重置新一期完成状态；同一期从“等待官方窗口”校准为确定时间时必须原位更新并保留完成状态。
- 个人完成判定只承认本期必须手动挑战部分的记录；自动继承、扫荡、减负结算和快速解锁不算手动完成。

### 地图

- 公共表只维护完整固定目录，个人接口只回写探索度。
- 个人 API 偶尔把基准二级地区作为独立 region 返回；唯一规范化标题可以绑定进度，但渲染层级仍以基准表为准。
- 只更新实际核验过的游戏的 `MAP_CATALOG_VERIFIED_AT`，时间不得写到未来。
