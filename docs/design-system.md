# Gtask 界面设计基线

更新时间：2026-08-23

本文用于约束 Gtask 后续界面维护。产品不再自创一套命名和规则繁多的视觉主题；界面以成熟设计体系为参照，再按桌面游戏清单的使用场景做必要适配。

## 1. 参考优先级

1. [Microsoft Fluent 2](https://fluent2.microsoft.design/)：暗色语义色、设计令牌、导航、列表、间距、圆角、焦点和 Windows 桌面观感。
2. [GitHub Primer](https://primer.style/)：密集信息列表、按钮与链接的可辨识性、状态反馈和无障碍底线。
3. Gtask 自身业务：游戏切换、清单完成、截止时间、同步状态和本机设置。

遇到视觉分歧时，先检查 Fluent 2 或 Primer 是否已有成熟模式；只有确实没有合适模式时才增加本项目规则。不得以“更有氛围”为理由加入无业务含义的渐变、发光、彩色描边或大面积状态底色。

## 2. 产品视觉原则

- **安静但不失信息**：界面表面使用午夜蓝中性色；蓝色表示信息与同步，黄色只表示临近，红色只表示错误、过期或破坏性操作，绿色只表示成功或完成。
- **清楚**：层级主要由字号、字重、间距和表面层级建立，不靠层层边框。
- **少打扰**：普通倒计时使用柔和信息蓝，未开始事项使用低饱和紫色，只有紧急时间才提升为黄色；已完成事项弱化并加删除线，不整行染绿。
- **像 Windows 应用**：优先使用 Segoe UI Variable、紧凑控件、小圆角、明确的 hover / pressed / focus 状态。
- **一处一个主动作**：同一行或同一弹窗只突出一个主要操作，其余操作使用次要或危险样式。
- **文案口语化**：用户界面不出现“基准表、凭据、适配器、公共清单”等维护术语。

## 3. 视觉令牌

令牌集中定义在 `src/renderer/src/styles.css` 的 `:root` 中。组件应使用语义变量，不应散落重复的原始色值。

- 背景：`--color-neutral-background-*`
- 文字：`--color-neutral-foreground-*`
- 分隔与边框：`--color-neutral-stroke-*`
- 品牌强调：`--color-brand-*`
- 信息与进度：`--color-info-*`、`--color-progress-*`、`--color-upcoming`
- 状态：`--color-success`、`--color-warning`、`--color-danger` 及对应的 `*-subtle`
- 形状：4 / 6 / 8 / 12 px 四级圆角，小控件使用更小圆角
- 控件高度：默认 34 px
- 阴影：只用于悬浮弹窗和拖动预览，不用于普通卡片

新增颜色前先确认现有语义令牌无法表达用途。不要直接按游戏各自的主色给功能版块染色；游戏图标已经承担游戏身份识别。

## 4. 组件规则

### 侧栏

- 只保留真实导航：游戏、回收站和设置。
- 当前游戏使用一处低饱和品牌底色和 3 px 选中指示，不叠加描边、阴影或位移动效。
- 版本时间默认使用柔和信息蓝；只有临近时使用警示色。
- 回收站和设置使用固定宽度图标槽，文字必须落在同一条垂直基线上；版本与本机存储说明归入侧栏底部，不能跟随主内容滚动。
- 窗口宽度不足时切换为 72 px 图标导航栏，不把游戏名、版本时间和功能文案同时截成省略号；图标按钮必须保留可访问名称和悬停提示。

### 任务页

- 页面标题显示当前游戏图标、游戏名和版本剩余时间。
- 每个版块只有一层容器；同版块的事项组成一个列表组，事项之间用细分隔线。
- 完成按钮、事项标题、标签和时间各自只表达一种信息，不用整行背景重复表达状态。
- 拖动手柄默认降低存在感，版块 hover 或键盘聚焦时再清晰显示。
- 版块同步属于次要信息操作，使用信息蓝但不使用持续可见的按钮描边；普通剩余时间使用柔和信息蓝，结束不足 48 小时时才提升为警示色。

### 设置

- 使用稳定的分类导航：游戏与同步、外观、账号与数据、软件更新。
- 每个分类只展示当前任务相关内容，避免一张超长表单堆满所有设置。
- 多款游戏的“显示 / 自动同步”放在同一张偏好表中，便于横向比较。
- 按钮宽度随文案变化，只保留合理最小宽度，不用统一固定宽度造成拥挤或超框。
- 同一设置卡片上下相邻的操作使用共享操作列；下拉框与按钮组对齐，只有一个操作时对齐相邻行最右侧按钮的中心线。
- 设置分类共享同一弹窗尺寸；切换分类时标题栏和分类导航不得位移，内容超出时只滚动右侧内容区。

### 弹窗

- 使用应用内弹窗，不调用 Windows 原生确认框。
- 普通弹窗只使用一层中性表面和一层阴影。
- 危险操作在文案、图标和主按钮上表达风险，不加入装饰性警报渐变。

## 5. 无障碍与验收

- 所有交互控件必须有可见的 hover、pressed、disabled 和键盘 focus 状态。
- 不以颜色作为唯一状态提示；选中项同时有形状指示，完成项同时有勾选和文字弱化。
- 尊重 `prefers-reduced-motion`，并为 Windows 强制颜色模式保留可辨识边界。
- 正式提交前至少运行 `pnpm typecheck`、`pnpm test` 和 `pnpm build`。
- 视觉改动完成后使用真实程序和隔离演示数据更新 `docs/assets` 快照；不得用设计稿冒充软件实拍。
- 同时检查正式 750×1000 与最小 540×720 窗口；除完整页面外，必须单独检查四个角、侧栏底部、滚动末端、文字基线和弹窗操作区。

## 6. 明确禁止

- 页面或普通卡片的装饰性线性 / 径向渐变
- 大面积高饱和蓝色背景、发光边框和多层卡片套卡片
- 用红色显示普通倒计时，或用绿色填充整条已完成事项
- 每个版块使用不同强调色但没有功能含义
- 为追求“品牌感”牺牲文字对比度、信息密度或操作可辨识性
- 未查成熟组件模式就新增一套自定义导航、弹窗或表单规则
