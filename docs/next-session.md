# 下次开发接续点

更新时间：2026-07-31（Asia/Shanghai）

## 当前架构基准

- 底层方针见 [sync-architecture-redesign.md](./sync-architecture-redesign.md)：规范清单负责身份与结构；已绑定数据及官方接口明确给出的身份、名称、进度、时间和结构事实走机械快路径，冲突、结构缺失和未知完成语义才进入 Codex。
- 数据库当前为 v24。来源绑定、账号隔离个人状态、语义规则、同步观察、版块覆盖度及取消状态均已持久化。
- 活动只管理限时活动；首次活动完成语义需要 Codex 确认并保存可复用规则，后续相同接口与官方 ID 机械更新。
- 周期挑战按稳定 `modeKey`、当期时间窗和周期身份匹配，本期只要有挑战记录即完成；官方完整字段可机械增量补入缺失当期，固定“周常”由应用维护并每周一重置。
- 地图固定为两级规范目录：一级主地区 `region` 与归属唯一主地区的二级地区 `subregion`。官方名称在规范目录内唯一时直接建立 ID 绑定；官方接口同时给出稳定 ID、本地化名称、探索度和结构化父子关系时，也可机械增量补齐缺项。冲突或父级不完整才交给 Codex。
- 原神、绝区零、鸣潮支持个人地图进度；星铁当前只建立地图目录，不展示伪造百分比。
- 用户关闭主窗口即退出应用：取消全部公开资料任务、个人请求和语义审核，终止应用启动的 Codex 子进程，不驻留后台。

## 已完成的本轮改动

- 根据用户提供的原神、绝区零、鸣潮官方界面截图固化名称与父子关系；截图中的 UID、探索度和其他个人数据未复制进项目。
- 星铁地图目录按当前公开资料建立，等待用户在试用版中人工复核。
- 绝区零接入官方战绩页实际使用的 `/api/zzz/exploration_detail`，解析区域组、二级区域、官方 ID 与探索百分比。
- 地图界面恢复一级下拉二级的两级树；所有目录默认收起，点击目录正文展开，菜单按钮编辑；地图使用横向双列布局并保留切换游戏时的展开及滚动状态。
- 公开地图同步先直接维护内置目录，不再为整张地图启动 Codex；个人地图首次同步会先机械建立目录，再绑定进度。
- 地图“同步清单”已升级为按需增量核验：先恢复内置目录，再根据基准核验时间、最近成功的 Codex 地图任务及当前版本窗口决定是否排队；同版本不重复启动 Codex，跨版本或目录超过 30 天才核验新增、改名与归属变化。
- 取消与退出链路覆盖个人请求、公开资料任务、语义审核、登录请求和 Codex Worker 进程树。
- 本轮自动化回归覆盖数据库迁移、目录约束、绑定快路径、取消、退出、绝区零区域收集和界面树结构。
- RC33 将官方确定事实与业务语义分开，并增加按版本窗口触发的地图增量核验；地图和周期走快路径，活动仍保留首次完成语义审核，语义批次保持 6 条并支持两个 Worker 分担。

## 正式试用版验收顺序

1. 从空数据库启动，确认每个游戏只有主线与支线，地图为空。
2. 分别点击地图“同步清单”，核对四游戏一级/二级目录、默认收起、双列布局和无重复根项。
3. 对原神、绝区零、鸣潮点击地图“同步进度”，确认官方 ID 初次绑定后直接写入百分比；官方结构完整的新地区应直接增量补入，只有冲突才进入 Codex。
4. 验证活动三态与周期 `modeKey + 当期时间窗` 快路径，确认历史周期不会被改写，只有异常候选进入 Codex。
5. 同时发起多个同步，再关闭主窗口；任务应立即取消，任务管理器中不应残留 Gtask 或其启动的 Codex 进程。
