# 下一次开发接续点

更新时间：2026-08-08（Asia/Shanghai）

## 当前基线

- 产品版本：Gtask 1.0.0；数据库当前 schema 为 v2，现有 v1 数据库启动时安全迁移。
- 公开数据与个人数据严格隔离，完整架构见 [sync-architecture-redesign.md](./sync-architecture-redesign.md)。
- 个人快照先机械建立；只有异常字段进入 `personal_review`，标签和缺失时间进入 `personal_metadata`。
- Codex 后台固定六个执行槽，默认 `gpt-5.6-sol / medium`，用户设置从下一个任务起生效。
- 地图只允许 `region/subregion` 两级结构；维护入口见 [ai-map-catalog-maintenance.md](./ai-map-catalog-maintenance.md)。
- 系统同步清单由同步快照维护，不提供用户删除入口；回收站只保留手动事项。
- 任务与固定周常版块均已移除；游戏版本倒计时由独立 `game_version_windows` 维护，并通过顶部全局同步菜单的“版本校时”刷新。
- 更新源通过可扩展 Provider 接入；1.0 发布前 URL 为空，空配置不发网络请求。

## 本轮已完成

### 周期挑战完成证据统一

- 四款游戏统一采用“本期必须手动挑战的目标存在记录即完成”，不要求满星、满分或全部通关。
- 原神只认本期实际战斗次数/战斗明细；星铁排除 `is_fast` 快速解锁层；绝区零式舆防卫战只认当前手动区成绩；鸣潮逆境深塔只认深境区未继承塔层，冥歌海墟只认第 9–12 关。
- 自动继承、快速解锁、扫荡、汇总星数、最高层，以及 `halfList`、`floorList`、`teams`、`levels` 等预生成结构本身均不构成手动挑战记录；零记录模板、自动记录、部分手动挑战和明确战绩均有解析回归。

### 固定周常彻底删除与 v1 → v2 迁移

- 固定周常已从分类、界面、数据种子、周期重置、公开同步协议、合并保护逻辑和测试中移除。
- v1 系统周常在迁移时删除；用户手动建立的旧周常转换为 `custom`，标题与完成状态保留。
- 新数据库直接创建 v2，未知或更高版本仍拒绝打开。

### 公开地图一级地区派生进度

- `public_schedule` 一级地区按直属二级地区探索度做简单平均；没有可靠面积权重时不编造加权算法。
- 子项进度修改、完成切换、公开同步新增或移除节点后都会立即重算父级；全部完成时父级为 `100%` 并完成。
- 启动时会把旧版中“公开二级地图已完成但进度仍为 0”的不一致状态无损归一为 `100%`，随后重新派生一级进度。
- `personal_sync` 的一级地区官方探索度不受本地派生逻辑影响。

### 公开活动目录状态与标签状态解耦

- 活动目录同步状态只反映目标覆盖、稳定身份及必要字段；未知玩法标签不再把完整目录降级为 `stale`。
- 重复同步的 `新增 0、更新 N` 继续作为幂等成功结果，并更新成功时间。
- 真正缺少目标版块或必要时间字段时仍保持部分同步/待补全状态。

## 继续开发前

1. 先阅读仓库根目录 `AGENTS.md` 和 `docs/sync-architecture-redesign.md`。
2. 保留用户未提交改动，不恢复公开/个人融合，也不恢复已删除的逐条语义审核 MCP 工具。
3. 数据结构继续从 v2 增加向前迁移；不得删除或重建真实数据库、凭据、备份和测试参照物。
4. 常规验证依次运行 `pnpm test`、`pnpm typecheck`、`pnpm build`。
