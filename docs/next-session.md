## 1. 项目是什么

Gtask 是一款面向 Windows 的本地游戏任务清单，技术栈为 Electron + Vue 3 + TypeScript + SQLite。它把多款游戏分散在游戏内菜单中的版本倒计时、限时活动、周期挑战、地图探索和用户自定义待办集中到一个界面。

当前内置游戏：

- 原神（`genshin`）
- 崩坏：星穹铁道（`star-rail`）
- 绝区零（`zenless`）
- 鸣潮（`wuthering-waves`）

产品目标是实用、清楚、少打扰，不做“发布会式”营销，不使用“领先、独创”等夸张文案。仓库宣传素材只使用真实软件界面快照，不制作广告海报。用户是个人发布者，不会编程，负责需求、交互判断和人工验收；代码、测试、构建与文档由 Codex 实现和维护。项目免费，不引入需要个人持续付费的服务器、对象存储或 CDN。

## 3. 不可破坏的架构边界

### 公共基准与个人进度

- 内置活动、周期、地图和版本窗口由持久的 `public_schedule` 公共基准所有。
- 米游社/库街区个人接口只能更新唯一匹配基准行的完成状态或探索进度，不能创建、替换或删除目录结构。
- 不得重新引入数据源切换、个人拥有的目录、个人语义复核或个人元数据补标。
- 自定义版块保持完整 CRUD；内置卡片不可新增、编辑或删除。
- 后台 MCP 是本机 Codex 管理员专用的公共基准维护接口，不向普通用户开放；用户只消费发布后的远程基准。它不是用户运行软件的依赖，也不能在 renderer 暴露 Codex、插件、Agent 或公共资料研究控件。

### 地图

- 地图永远只有 `region` / `subregion` 两级。
- 已发布 `remoteKey` 必须稳定；改名保留机器身份。
- 维护地图前必须完整阅读 `docs/ai-map-catalog-maintenance.md` 并运行地图专项测试。

### 周期挑战

- 每种玩法跨所有期次永久复用同一个 `modeKey` 和 `remoteKey`；`periodKey` 只表示当前期次。
- 普通换期由客户端按照稳定锚点、开启间隔 cadence 和持续时间自动计算，不能按期次新建卡片，也不能把日期拼进 `remoteKey`。
- 版本核查时，如果官方没有改变模式、重置规则或排期锚点，周期部分完全不动。
- 只有官方新增/移除/改名玩法，或改变重置规则/锚点时，才允许更新周期基准或热更新。
- 持续时间不一定等于开启间隔：幽境危战和鸣潮终焉矩阵存在约 8 天空档。空档中 UI 应显示“距离开始”，不能把上一期持续时间当成下一期开启间隔。

- 星铁 4 项：混沌回忆、虚构叙事、末日幻影、异相仲裁。

- 鸣潮 3 项：逆境深塔、冥歌海墟、终焉矩阵。

### 版本倒计时

- 常规版本按每款游戏配置的既定周期自动续算。
- 版本核查时，如果版更节奏没有改变，不发布 `versionWindow`，也不为方便测试递增产品版本。
- 只有官方延期、缩短、延长或其他常规规则无法表示的例外，才通过热更新校准版本窗口。
- 原神 7.0 下一次维护尚未官宣时使用 42 天低置信度预测；后续官宣若确认仍是常规节奏则完全不动，只有精确时刻偏离常规预测时才发布最小 `versionWindow` 校准。

## 4. 远程热更新与软件版更

### 清单热更新

- 唯一入口：`updates/catalog.json`，schemaVersion 为 1。
- 仅允许变更 `public_schedule` 的活动、周期、两级地图和例外版本窗口；禁止完成状态、探索度、账号、Cookie、Token、凭据或 `custom` 项。
- GitHub 为权威；Gitee 为免费镜像。自动来源比较两个源，同 revision 优先镜像，内容冲突以 GitHub 为准，旧 revision 不得覆盖新状态。
- 四款游戏在一个 SQLite 事务中原子合并；任一数据非法则整批回滚。
- 自动启动检查持久静默 24 小时。手动“更新清单”失败可立即重试；成功后静默 1 小时，按钮显示“XX分重试”。
- 2026-08-13 已完成真实链路测试：Gitee 成功返回并应用 `2026-08-13.genshin-cycle-identity-correction`。
- 发布步骤详见 `docs/remote-catalog-feed.md`。任何维护任务都必须先检查目标版块的完整范围，再只提交相对当前基准的实际增删改；时间不变不校时、内容不变不重写。无差异时用 `verifiedUnchangedTargets` 记录核查完成，不能为了“完整”重复下发版本窗口、活动、周期或地图。
- 当前待发布清单修订为 `2026-08-20.wuwa-3.6-zenless-3.1-refresh`：鸣潮新增 6 个 3.6 活动，绝区零仅修正“回归丽都：羽落重逢”标题标点；其余绝区零 3.1 活动未变化。
- 同轮周期与地图全量核查均无可写差异。鸣潮“全息战略・演武”的新挑战内容不新建周期模式；“玄元境”仅被官方确认成剧情新场景，尚无证据表明它是库街区探索度接口的独立目录节点，因此地图基准不猜父级、不新增。绝区零 3.1 的周期与区域探索目录不变。

### 软件版更

- `updates/latest.json` 只描述正式软件版本和 GitHub/Gitee Release 地址。
- 设置中的“自动/Gitee/GitHub”同时控制软件更新与清单热更新来源。
- 自动软件更新检查同样持久静默 24 小时。
- 只有用户明确批准某个具体版本发布，才允许修改 `package.json` 版本、更新版本说明、创建 `v*` 标签或触发 Release 工作流。
- 发布工作流只构建一次并上传 GitHub Release；随后用 `GITEE_TOKEN` 将同一安装包、便携包和校验文件发布到 Gitee。不得新增付费镜像基础设施。

## 5. 本轮最后修复

原神 7.0 热更新曾错误创建两张按期次命名的新卡：

- `endgame:spiral-abyss:2026-08-16`
- `endgame:imaginarium-theater:2026-09-01`

根因有两层：旧维护契约误导维护端为每一期生成独立 `remoteKey`；旧换期算法又用“上一期持续时间”推算下一期开启时刻，无法处理有空档的玩法。

已完成：

- 归档上述两张错误卡，保留正确稳定行及用户完成状态。
- 数据库合并入口和远程 feed 校验都拒绝已知周期模式使用非规范稳定键，并拒绝同一 mode 重复出现。
- 周期维护契约升至 schema 14，明确普通新一期不是新记录。
- 换期算法改为：有效观测窗口只在仍处于活动期时使用；过期后回到固定锚点 + cadence 计算。
- 幽境危战按 42 天 cadence 正确进入空档，并在 2026-08-19 开启下一期。
- 同类修复自动覆盖鸣潮终焉矩阵；星铁、绝区零及其他连续模式持续时间等于 cadence，行为保持不变。
- 修复已合入 PR #9，并覆盖部署至 `D:\Git\Gtask`。

## 6. 已实现的重要产品行为

- 新用户无需登录即可看到四款游戏的完整公共基准。
- 支持版块提供“同步进度”；未登录时弹窗进入米游社/库街区登录。
- 启动自动个人进度同步按游戏开关，并有本地 10 分钟启动冷却；手动同步不受该冷却限制。
- 版块同步标记只出现在确有个人接口能力的版块。
- 原神和星铁活动只采信官方接口明确的“全部完成”字段。
- “只看未完成”只根据清单状态决定可见性；后台同步完成时不会让已隐藏版块闪现约 500ms。
- 已完成地图父项在未完成筛选中隐藏，仍未完成的子地区临时提升；探索度 100% 视为完成。
- 同步过程卡、结果通知和取消入口已删除；后台同步安静更新数据。
- 设置页所有布尔开关使用统一开关样式；顶部“只看未完成”采用文字 + 独立 switch，不让整个容器表现为按钮。
- README 快照是隔离演示数据的原始软件 UI；设置页快照已包含“更新清单”按钮。

## 8. 下一步与长期维护

当前没有已知阻塞性缺陷，下一窗口首先接收用户的新需求。若主动维护：

1. 等原神下一版本维护时间官宣后，只校准 7.0 版本窗口的例外终点；若仍是常规周期则不做热更。
2. 每个游戏版更时核对实际新增/结束的活动和地图；版本节奏、深渊规则未变则对应数据完全不动。
3. 官方增加新周期模式或调整排期时，再修改 `cycle-catalog.ts`、契约、热更新和回归。
4. 官方个人接口变化时只更新对应 adapter/parser 及测试，不允许个人数据拥有目录。
5. 新数据库 schema 必须追加向前迁移，并先创建迁移前备份。
