# 数据模型与同步不变量

## 支持范围

当前版本只允许以下游戏 ID：

| ID | 游戏 |
|---|---|
| `genshin` | 原神 |
| `star-rail` | 崩坏：星穹铁道 |
| `zenless` | 绝区零 |
| `wuthering-waves` | 鸣潮 |

渲染进程传入的游戏 ID 必须在主进程再次校验，不能依靠界面选项限制。

## 清单分类

| 分类 | 用途 |
|---|---|
| `main_quest` | 主线是否完成，不记录具体任务 |
| `side_quest` | 支线是否完成，不记录具体任务 |
| `limited_event` | 有结束时间的限时活动 |
| `permanent_event` | 用户维护的常驻活动 |
| `weekly` | 默认周一重置的周常事项 |
| `endgame` | 按游戏、模式和周期记录的深渊类玩法 |
| `exploration` | 地图区域及可选百分比 |
| `custom` | 任意用户事项 |

每款游戏首次初始化时只生成一条主线状态和一条支线状态。它们使用稳定 ID，软删除后不会因下次启动而重新出现。

## 来源与完成状态

`source` 有三种取值：

- `manual`：纯手动项目。
- `public_schedule`：公开排期，不含个人状态。
- `personal_sync`：登录后取得的个人数据。

用户手动完成事项时：

1. `completed` 设为 `1`。
2. `completed_at` 记录首次完成时间，用于本周统计。
3. `manual_completion_locked` 设为 `1`。
4. 当前周期内的远端同步不得把它改回未完成。

用户主动改回未完成时，清除 `completed_at` 和 `manual_completion_locked`。

## 删除语义

界面删除只将 `archived` 设为 `1`，不执行物理删除。这样可以：

- 防止同步失败误删历史数据。
- 防止有 `remote_key` 的远端事项被下一次同步立即重新创建。
- 为以后提供回收站或恢复功能保留空间。

## 同步状态

每款游戏在 `sync_states` 中独立保存：

- 模式：`manual`、`public_schedule`、`personal_sync`。
- 状态：`idle`、`success`、`error`、`stale`、`verification_required`。
- 最后尝试时间、最后成功时间和说明信息。

同步适配器后续必须使用事务更新，并遵守：

- 不删除手动项目。
- 不覆盖当前周期内的手动完成锁。
- 请求失败时保留最后一次成功数据。
- 远端缺少旧地图或旧活动时不直接删除本地记录。

## 数据库版本

- v1：游戏、清单、同步状态和远端身份索引。
- v2：增加 `completed_at`，用于本周完成统计。

数据库启动时开启外键约束和 WAL。后续结构变化必须新增迁移版本，不能直接假定用户数据库是空库。
