# 数据模型

## 清单版块

| 版块 | 类别 | 结构权威 | 用户权限 |
|---|---|---|---|
| 活动 | `limited_event` | 公共基准表 | 完成状态 |
| 周期挑战 | `endgame` | 公共基准表 | 完成状态 |
| 地图探索 | `exploration` | 两级公共基准表 | 完成状态 |
| 自定义 | `custom` | 用户 | 新增、编辑、完成、删除、恢复 |

内置行使用 `public_schedule`，个人同步只更新这些行的状态；`personal_sync` 仅作为旧数据兼容和同步内部来源标识，不再拥有独立目录。用户行使用 `manual`。

## 基准字段

活动保存稳定键、名称、玩法标签、开始/结束时间和来源。周期保存模式键、周期键、窗口、滚动规则和来源。地图只允许无父级 `region` 与恰好归属一个 `region` 的 `subregion`。版本窗口独立保存在 `game_version_windows`，不进入清单或回收站。

包内基准携带核验时间。启动时只用更新的包内基准覆盖旧数据，后台热维护得到的更新记录不会被旧发布包覆盖。

## 完成与进度

- 用户标为完成时记录 `completed_at` 并设置 `manual_completion_locked`；用户改回未完成时清除二者。
- 官方接口有可靠状态时可更新完成/探索度；不能证明时保留用户状态。
- 地图完成对应 `progressPercent = 100`；一级公开地图可由直属二级进度派生，但官方个人一级值不会改写地图结构。
- 周期模式本期存在已验证的手动挑战记录即完成，不要求满星、最高层或全部目标。
- 周期到期后写历史并原位滚动到当前期，清除旧期绑定、完成状态和手动锁。

## 个人同步审计

`source_bindings` 保存 `provider + endpoint + externalId` 到基准行的唯一绑定。`personal_sync_snapshots` 保存脱敏账号作用域、目标、适配器版本、数量和激活时间。凭据、UID、Cookie 和 Token 不进入数据库同步表或日志。

完整响应先规范化、验证身份和范围，再在单事务中写入匹配基准行、绑定、快照审计和同步状态。未匹配项忽略；失败和部分响应整批回滚。

## 删除与回收站

只有 `manual/custom` 行可软删除、批量归档和恢复。系统基准行不能通过界面或普通 IPC 删除。后台基准维护可在契约范围内归档错误、重复或过期的系统行，但不能触碰手动数据。

## 数据库与备份

- 当前 schema：v3。
- v1 → v2 删除旧固定周常并把用户周常迁入自定义。
- v2 → v3 增加按游戏自动同步开关，迁移内置手动项，种完整基准并吸收旧个人进度，删除废弃个人复核缓存。
- 启动启用 WAL、外键约束和忙等待；未来版本数据库拒绝打开。
- 每日备份最多保留 30 份；手动、迁移前和恢复前备份不参与自动轮换。
- 数据库/备份位于系统文档目录，凭据位于 AppData 的 DPAPI 加密目录，清理程序文件不得触碰这些目录。
