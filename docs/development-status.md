## 当前数据决策架构

- 公开资料由 Codex 负责建立和补全规范目录；个人进度优先按持久官方 ID/稳定来源键与已确认字段语义机械写入。官方接口事实足以唯一确定的地图或周期增量也直接走快路径，只有冲突、结构缺失和未知字段进入 Codex。
- 个人入口可在空清单中先建立局部目录，公开入口后续原位补全；项目 ID、来源绑定、个人状态和手动锁保持不变。
- 个人语义候选按同一游戏、版块、账号和采集批次以每批 6 条领取，让两个语义 Worker 能分担积压；候选不会重复联网证明已经标记为官方确定的字段。
- 公开资料任务和个人语义候选都会向 Codex 提供当前版块的安全匹配候选；Codex 使用明确的 `matchItemId` 决定原位更新，否则视为新增。数据库只按 ID/稳定远端键执行，不再二次猜测是否为同一事项。
- Codex 可将确认错误、重复或失效的同步事项移入回收站，所有启用游戏规则一致。同步流程不能自动删除手动事项、主线、支线和固定周常；所有删除均可恢复。
- 应用仅保留字段类型、数值范围、事务、游戏/版块归属、固定项、手动完成锁、未来活动不能完成等机械或产品不变量。
- 活动版块只管理限时活动，并提供玩法标签筛选；所有启用游戏共用同一组件。

- 首次同步建立“周常”后将其转为不可删除的长期状态项；周常统一每周一按官方服务器时区自动重置，完成后立即沉到版块末尾，下周重置后回到未完成队列。
- 活动、周期事项、地图探索均有独立同步菜单；任务版块固定为主线/支线，只保留“版更校时”，不显示清理已完成或新增入口。
- 版块同步任务在 Agent 检索、个人适配器过滤和数据库回写三层限制目标类别，禁止跨版块写入。
- 地图使用经人工资料校对的内置规范目录，且只有“一级主地区 / 归属于该主地区的二级地区”两层。首次新增节点为 0%，目录维护不覆盖个人进度；个人数据只提供官方 ID 和探索度，优先建立稳定绑定后机械合并，未知或冲突节点才交给 Codex。
- 地图清单同步不会每次重审整表：应用以当前版本窗口和独立的 Codex 核验时间判断是否需要增量审计；需要时 Codex 只检索基准表之后的新地区、改名或归属修正，没有变化即可空提交。
- 未完成事项先按生命周期再按时间排序：正在进行且进入结束前最后 24 小时的事项最优先，其次是其他正在进行事项，再后是尚未开始事项（按开始时间）；已过期未完成项靠后，已完成事项统一沉底。“距离开始”不会与“剩余结束”混在同一优先级比较。
- 只有周常按上海服务器时间在每周一自动重置。深渊/挑战不再本地自动滚动；公开资料用稳定模式键和每期独立的周期键/远端键新增记录，已完成旧期保持完成。
- AI/MCP 公开资料写入只接受带 `Z` 或明确 UTC 偏移量的时间；任务同时携带用户系统时区，海外来源需先确认服务器时区和夏令时，再保存绝对时刻。
- 已移除本地 OCR、“同步本地”菜单、图片解析 IPC、Tesseract 运行库和语言模型。离线场景使用完整的手动新增/编辑，不再用低可靠识别结果增加用户校对负担。
- 深渊/挑战模式保存模式标识、周期键和起止时间；进入新周期时新增独立事项，不改写旧期完成状态。
